# 料力榜数据更新与离线包发布指南

本文件是 README 的详细补充。若与 README 冲突，以 README 中“`data.js` 必须在 ZIP 内且与 `index.html` 同级”的规则为准。

## 两套产物，不可混用

| 用途 | 目录 | 数据文件 | 是否提交到公开仓库 |
| --- | --- | --- |
| 网站部署 | `dist/` | `dist/data.js` | 是 |
| 小红书移动端离线包 | `artifacts/liaolibang-minitool/` | `artifacts/liaolibang-minitool/data.js` | 否 |

同一份 `料力榜.xlsx` 必须分别生成两份 `data.js`。不要把 `dist/data.js` 当作离线包交付物，也不要只更新网站数据而遗漏移动端目录。

## 更新源表

将最新版 Excel 放到根目录，文件名固定为 `料力榜.xlsx`。源表字段为：日期、期数、品牌、料包、色香味、还原度、易用性、料力评分、评语、视频链接。

品牌或料包为空的记录不会进入榜单。分数字段空白、`-` 或公式错误显示为 `-`，并在排序时保持最后。原始 Excel 属于私有数据，不得提交到公开仓库。

## 生成两套数据

```bash
# 网站数据与无 JavaScript 兜底榜单
uv run python scripts/build_data.py

# 离线包数据：输出路径必须指向移动端工作目录
uv run python scripts/build_data.py \
  料力榜.xlsx \
  artifacts/liaolibang-minitool/data.js

# 离线包仅使用经典脚本，且不能携带外部视频 URL
perl -pi -e 's/globalThis\.LIAOLI_DATA/window.LIAOLI_DATA/; s/,"video_url":"[^"]*"//g' \
  artifacts/liaolibang-minitool/data.js
```

完成后先确认文件存在：

```bash
test -f dist/data.js
test -f artifacts/liaolibang-minitool/data.js
```

## 离线包目录契约

`artifacts/liaolibang-minitool/` 是唯一的打包输入目录。打包前，其中至少要有以下六个文件：

```text
index.html
styles.css
app.js
data.js
favicon.png
crown.png
```

其中：

- `index.html` 是 ZIP 根目录入口，并使用相对路径加载 `./data.js` 与 `./app.js`。
- `data.js` 是当前榜单数据，必须位于该目录；其内容会直接进入 ZIP。
- `app.js` 是经典脚本，不使用模块导入。
- 图片与样式必须为本地文件，不得依赖网络资源。

## 校验、打包与复核

先运行应用测试：

```bash
UV_CACHE_DIR=/private/tmp/uv-cache uv run python -m unittest tests/test_build_data.py -v
node --test tests/app.test.mjs
node --check artifacts/liaolibang-minitool/app.js
```

安装并阅读 `minitool-zip-builder 1.8.0` 后，按下列顺序执行：

```bash
# 1. 审计目录，确保 data.js 已进入打包输入目录
python3 .codex/minitool-zip-builder/scripts/audit_artifact.py \
  artifacts/liaolibang-minitool

# 2. 从输入目录内部压缩其“内容”
cd artifacts/liaolibang-minitool
zip -r ../liaolibang-minitool-版本号.zip . -x '*.DS_Store'
cd ../..

# 3. 审计 ZIP，并人工确认 data.js 在 ZIP 根目录
python3 .codex/minitool-zip-builder/scripts/audit_artifact.py \
  artifacts/liaolibang-minitool-版本号.zip
unzip -l artifacts/liaolibang-minitool-版本号.zip
```

如果 `unzip -l` 输出出现 `liaolibang-minitool/data.js`，说明多包了一层目录，必须重新打包；正确输出是根目录的 `data.js`。

如果 ZIP 内没有 `data.js`，说明只更新了 `dist/data.js` 或在压缩前漏了生成移动端数据。必须回到“生成两套数据”步骤，不可直接上传。

## 发布前人工验证

审计通过只代表静态检查通过。将同一 ZIP 上传至创服平台后，先在平台模拟器完整验证，再分别用 Android 和 iOS 真机扫码验证。

## 公开仓库同步

提交前确认：

```bash
git status --short
git diff --check
```

仅提交网站代码、`dist/`、测试和文档。不要提交 `料力榜.xlsx`、`.codex/` 或 `artifacts/`。
